# SANATANA — The Living Knowledge Graph

*Explore the interconnected universe of Hindu literature, mythology, history, and heritage.*

A research-grade, provenance-first knowledge graph and interactive microsite. Texts,
passages, characters, deities, narratives, places, temples, inscriptions, objects and
manuscripts are records; every relationship between them is an **assertion** that carries its
sources (with exact locators), an evidence class, a confidence level and a verification
status. Tradition, textual attestation, scholarly interpretation and archaeological evidence
are kept distinct throughout.

## What is in the box

| Path | What it is |

| `data/entities/*.json` | Full records, one file (or `<agent>-<part>.json` files) per research agent |
| `data/assertions/*.json` | The edges — every one sourced |

| `data/comparisons/*.json` | “What each text says” tables, unreconciled |
| `data/sacred-chronology.json` | The traditional yuga / manvantara / kalpa chronology, kept apart from historical time |
| `data/discoveries.json` | Curated research discoveries, each with its evidence and caveat |

| `scripts/publish-villa.ts` | Builds with base `/sanatana/` and copies into `../villa/public/sanatana` |

## Running it

```bash
cd sanatana
npm install
npm run validate        # integrity check of the research data
npm run dev             # compiles the graph, then serves at http://localhost:5173
npm run build           # compile + typecheck + production build into dist/
npm test                # data-integrity and search tests
```

Node 22.6 or newer (the scripts run TypeScript directly through Node’s type stripping).

`npm run graph` (and therefore `dev` and `build`) **refuses to publish while validation errors
remain**. Use `npm run graph -- --allow-errors` only for a local preview.

## Deployment

**Live: https://hk.hkfire.app/sanatana/** — public (no access key). It is served by the Vercel
project that builds the repository root (`meridian`): the root `build.ts` copies the committed
build in `villa/public/sanatana/` into `dist/sanatana/`, and the root `middleware.ts` leaves
`/sanatana/` — and every path on `sanatana.hkfire.app`, once that domain is added to the
project — outside the memos' key gate.

To publish a change: edit, `npm run publish:villa` (validates, typechecks, builds with base
`/sanatana/` and copies into `villa/public/sanatana/`), commit, push to `main`.

- **As part of the villa site** (served at `/sanatana`): the same `villa/public/sanatana/` build;
  `villa/next.config.ts` rewrites `/sanatana` to its `index.html`.
- **Standalone** (Vercel, Netlify, any static host): create a project whose root directory is
  `sanatana/`; `vercel.json` sets `npm run build` and `dist/`. The build uses relative paths and
  hash routing, so it also works from any sub-path or from a plain folder.

## Refreshing the data

1. Edit or add records under `data/` following `research/AGENT-CONTRACT.md`.
2. `npm run validate` until it reports 0 errors.
3. `npm run build` (or `npm run dev`). The compiled graph, the exports and
   `research/audit/validation-report.md` are regenerated.

To add a shared identity, add it to `scripts/seed-core.ts` and run `npm run seed:core`.

## Using the data elsewhere

- **Neo4j**: copy `exports/nodes.csv` and `exports/edges.csv` into the import folder and run
  `exports/neo4j-import.cypher` (requires APOC), or use `neo4j-admin database import`.
- **PostgreSQL**: `nodes.csv` / `edges.csv` load directly with `\copy`.
- **Anything else**: `exports/graph.json` is the whole graph as one JSON document.

## Methodology in one paragraph

Research was split among six specialist agents (Vedic; epic; Purāṇic; regional and Southeast
Asian; archaeology, inscriptions and manuscripts; temples and sacred geography), each working
to `research/AGENT-CONTRACT.md` against a shared registry of canonical identities, followed by
an independent verification pass (`research/verification-report.md`). Evidence classes describe
the *nature* of evidence (text, manuscript, inscription, object, scholarship, tradition,
disputed), not the value of a tradition. Dates live in four separate systems — scholarly
textual, material, reception and traditional — and are never drawn on one axis unlabelled.
Network metrics describe the dataset, which reflects research coverage, and are never offered as
measures of religious importance or historical truth. See `research/00-research-blueprint.md`.

## Honest limits

The graph is deep on selected journeys rather than exhaustive. Of 3,648 assertions, 58% are
verified online and 22% source-checked; 12% have been checked only against a reference work
and 6% await a check — the site shows the status on every record. An independent review of
174 sampled assertions found no factual errors; its 52 findings are resolved and logged.
Coverage is weighted toward well-published Sanskrit, Tamil and monumental material, and no
human specialist has reviewed it yet. See `research/research-audit.md`.
